# Regler for edge-funktioner

- Web Push: afsendelse kun via supabase/functions/_shared/push.ts (fejler aldrig den kaldende alarm, respekterer push_preferences, 404/410 deaktiverer); faste tekster uden beløb/navne i _shared/pushText.ts spejlet i src/lib/push/pushText.ts; push-handlers i public/push-sw.js via workbox.importScripts. Why: push er kun ekstra kanal ved siden af mail og må ikke ændre caching.
- InvoiceFlow: adgang kun via `invoiceflow_access` (scope owner/own_automations/bookkeeping) og INVOKER-funktionen `invoiceflow_has_access`; logins krypteres kun i edge (`_shared/invoiceflow.ts`, AES-GCM med INVOICEFLOW_VAULT_KEY), `ciphertext`/`iv` har ingen kolonne-grant til authenticated, og intet endpoint returnerer klartekst; mailregler matches kun i `_shared/invoiceflowMailMatch.ts`. Why: logins må aldrig kunne læses fra appen, og adgangen skal kunne udvides uden kodeændring.
- InvoiceFlow-portaler: kun slugs i `invoiceflow_portal_catalog` med modul i `PORTAL_MODULES` (`_shared/invoiceflowPortalPeriods.ts`) køres, via `_shared/invoiceflowPortal.ts` (Browserbase eu-central-1, én persistent context pr. login i `browser_context_id`, keepAlive-sessioner, session-id på hver run); uventet layout = PORTAL_LAYOUT/pauset. Engangskode: job → afventer_kode, ejeren taster koden kun i Browserbase Live View (URL hentes frisk via invoiceflow-admin for credential-ejeren, gemmes aldrig), og opfølgning sker i `invoiceflow-cron` task code_wait som selv-kædede ~100 s kørsler kun mens der ventes; 15 min uden kode = PORTAL_CODE_TIMEOUT/pauset. Why: edge-funktioner kan ikke køre 15 min, og koder må aldrig passere Stork.
- Tryg-ugerapporten (weekly-lead-closure-report) er en selvkaldende kæde; vagthund-cron `weekly-lead-closure-watchdog` (action watchdog, hvert 5. min) genstarter kørsler uden opdatering i 5 min og alarmerer km@ mandag kl. 09 uden sendt mail; chainNext genforsøger platformens RateLimitError. Why: kæden døde stille, når platformen afviste næste kald.
- Tryg-ugerapportens uger låses i `weekly_lead_closure_locks`, når mandagsmailen er sendt; triggeren `weekly_lead_week_lock_guard` afviser skrivning til låste uger i `weekly_lead_closure_stats`/`weekly_lead_call_stats`, og cron tæller kun den netop afsluttede uge. Oplåsning kun via `unlock_weeks` + `unlock_order` (logges på kørslen). Why: Tryg afstemmer tal 1:1, og sendte tal må aldrig ændres bagud.
- Udsendelser (mail/SMS/push) går gennem `_shared/udsend.ts` (`udsend`/`udsendFlere`), som logger én række pr. modtager i `udsendelser` og respekterer `udsendelsestyper.aktiv`, stille timer (kun push), modtagerreglen via `udsendelse_tilladt` (bruger-id eller opslag fra medarbejder-id; ukendt = tjek springes over) og `udsendelsespraeferencer`; modulet er fail-open, og ukendte typer oprettes automatisk. `_shared/push.ts` går altid gennem modulet. Why: ét sted at se, slå fra og fravælge alt, Stork sender ud.
